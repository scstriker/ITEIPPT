# 生成内容 {#ch-um-generate}

[[AI 内容生成]]卡片在“规划框架”页面的下半部分。AI 按当前框架为每张正文页起草正文、表格或图片描述。内容生成成功后，才能进入“配图导入”和“审计预览”。

## 生成前检查 {#sec-um-gen-check}

{{i:开始生成内容}}[@fig-um-gen-card] 是还没有生成内容时的卡片。[[开始生成内容]]在以下情况不可点击：还没有解析成功的文档、框架中没有章节，或者有对话框正在执行。

![生成前的“AI 内容生成”卡片](shot:gen-card){#fig-um-gen-card .w95}

点击按钮后，系统先检查框架。章节名称或子章节名称为空时，不弹出对话框，卡片中直接显示错误，如[@fig-um-gen-validate] 所示。检查的项目和提示原文见[@tbl-um-gen-validate]。

![章节名称为空时的错误提示](shot:fw-validate){#fig-um-gen-validate .w95}

Table: 生成前检查的项目 {#tbl-um-gen-validate cols=30,70}

| 检查项目 | 不满足时的提示 |
|---|---|
| 至少有 1 章 | “请至少保留 1 个章节。” |
| 每章都有名称 | “第 n 章标题不能为空。” |
| 每章至少有 1 个子章节 | “第 n 章至少需要 1 个子章节。” |
| 每个子章节都有名称 | “第 n-m 子章节标题不能为空。”，n 是章号，m 是子章节序号 |

## 开始生成 {#sec-um-gen-run}

{{i:生成任务}}检查通过后，按下面的步骤生成内容。

1. 点击[[开始生成内容]]。弹出“确认开始生成内容？”对话框，正文写明将生成约多少页。要再看一遍框架，点击[[再检查一下]]。
2. 点击[[开始生成]]。对话框保持打开，两个按钮变为不可点击。卡片中的按钮变为[[任务执行中...]]，旁边显示任务 ID 和进度条，如[@fig-um-gen-progress] 所示。

    ![生成过程中的对话框（编号 1）和进度条（编号 2）](shot:gen-progress){#fig-um-gen-progress .w100}

3. 等待进度走到 100%。对话框自动关闭，卡片显示生成结果，见 [@sec-um-gen-result] 节。

{{i:进度}}进度条左侧的文字表示任务所处的阶段，见[@tbl-um-gen-stages]。百分比按完成的批次计算，生成期间在 1%～99% 之间变化。

Table: 生成进度的阶段文字 {#tbl-um-gen-stages cols=40,60}

| 阶段文字 | 含义 |
|---|---|
| “正在创建任务” | 浏览器正在把文档文字和框架提交给后端 |
| “排队中” | 后端已收到任务，等待执行 |
| “正在准备任务” | 后端开始执行任务 |
| “正在生成内容（批次 a/b）” | 正在请 AI 起草第 a 批，共 b 批，每批 4 张正文页 |
| “正在整理结果” | 所有批次完成，正在汇总结果和缺失项 |
| “已完成，结果已就绪” | 浏览器已取回结果 |

## 生成任务的执行过程 {#sec-um-gen-job}

{{i:生成任务/执行过程}}内容生成在后端以任务方式执行，浏览器不必一直保持连接。任务的状态变化如[@fig-um-job] 所示。

![生成任务的状态变化](diagram:job){#fig-um-job .w100}

执行过程有以下规则：

- 后端把正文页按 4 页一批，依次请 AI 起草。
- 浏览器每 2 秒查询一次进度。等待超过 20 分钟仍未完成，浏览器按失败处理，提示重新生成。
- 后端从任务开始计时，约 8 分钟时还没轮到的批次不再请 AI 起草，改用规则从原文中摘取片段补写，结果标为降级，见 [@sec-um-degraded] 节。
- 任务的输入和结果在后端保存 72 小时，之后由每天运行一次的清理任务删除。

## 生成结果 {#sec-um-gen-result}

{{i:生成结果}}生成成功后，卡片显示[[已生成页数：]]和[[原文覆盖率：]]，如[@fig-um-gen-done] 中编号 1 所示。此时[[下一步 →]]（编号 2）可以点击。

![生成成功后的卡片](shot:gen-done){#fig-um-gen-done .w95}

{{i:原文覆盖率}}已生成页数包括封面、目录过渡页、正文页和结束页。原文覆盖率是正文页中“原文精确引用”页所占的百分比，例如 13 张正文页中有 5 张，覆盖率为 38.46%。来源置信度的 4 个等级见[@tbl-um-confidence]。

生成结果的结构如下：

- 第 1 页是封面，最后 1 页是结束页，结束页写“敬请指正”。
- 每章先有 1 张目录过渡页，列出全部章节并突出当前章。
- 每个子章节生成 1 张正文页。

每张正文页包含[@tbl-um-gen-fields] 中的内容。

Table: 正文页包含的内容 {#tbl-um-gen-fields cols=22,78}

| 内容 | 说明 |
|---|---|
| 正文 | 1～3 句话。系统要求 AI 写 80～220 个汉字，实际长度可能超出 |
| 语义高亮 | 正文中最多 2 处关键短语，导出后显示为红色 |
| 来源引用 | 正文依据的原文位置，由 AI 给出，例如原文的章节号或段落标题，见 [@sec-um-audit-source] 节 |
| 来源置信度 | 正文与原文的关系：原文精确引用、原文转述、AI 推断或 AI 补充构建 |
| AI 补充项 | AI 在原文之外补充的内容，见 [@sec-um-audit-supplements] 节 |
| 表格 | 布局为“文字 + 表格”的页面才有，包括表头和数据行 |
| 图片描述 | 布局为“文字 + 图片”的页面才有，每条描述对应一个图片槽位 |

生成成功后，[[开始生成内容]]可以再次点击。重新生成会用新结果替换旧结果，审计预览中的修改全部丢失，导入的图片保留，见 [@sec-um-stale] 节。

## 框架改动后内容失效 {#sec-um-stale}

{{i:内容失效}}生成的内容只对生成时的框架有效。生成之后，只要改动下列任何一项，内容就失效：

- 所选的预设模板；
- 章节名称；
- 子章节的名称、数量或布局；
- 再次执行 AI 建议调整，并且 AI 改变了布局。

内容失效后，[[AI 内容生成]]卡片显示警告，[[下一步 →]]不可点击，提示行写明原因，如[@fig-um-gen-stale] 所示。步骤条上的“配图导入”和“审计预览”变为灰色。

![内容失效后的警告和不可点击的“下一步”](shot:gen-stale-nav){#fig-um-gen-stale .w95}

把框架改回生成时的样子，内容会恢复有效。名称首尾的空格不影响判断。

内容失效后重新生成，系统做以下处理：

- 生成新的逐页内容，替换旧内容。审计预览中的修改全部丢失。
- 已导入的图片保留，仍按页码和槽位对应。框架变化后页码可能移动，图片可能落到其他页上，要在“配图导入”中逐页核对。

!!! warning "注意"
    已经在审计预览中改过正文时，不要再改框架。必须改框架时，先把改过的正文复制到别处保存。

## 降级生成 {#sec-um-degraded}

{{i:降级/生成}}后端请 AI 起草时，个别批次可能失败，或者整个任务运行时间过长。这时任务不会中断：失败的页面改用规则从原文中摘取片段补写，结果标为“降级”。卡片中显示警告“已降级生成，可继续编辑（原因：……）。”，如[@fig-um-gen-degraded] 中编号 1 所示。

![降级生成后的警告](shot:gen-degraded){#fig-um-gen-degraded .w95}

括号中的原因是英文代码，含义见[@tbl-um-degrade]。

Table: 降级原因代码 {#tbl-um-degrade cols=34,66}

| 原因代码 | 含义 |
|---|---|
| batch_generation_failed | 某一批页面请 AI 起草失败，这批页面用规则补写 |
| soft_deadline_reached | 任务运行约 8 分钟时还有批次没轮到，剩余页面用规则补写 |
| request_level_fallback | 整个生成过程出错，全部正文页用规则补写，冒号后面是出错原因 |

降级的结果可以照常进入后面的步骤。补写的页面在审计预览中都有缺失项，提示“本页生成阶段遇到上游异常，系统已自动补写正文以保证流程可继续。”或“本页正文由低证据或自动归纳补全生成，建议人工复核关键结论与数据。”。这些页面要逐页核对，见 [@sec-um-audit-missing] 节。

!!! note "说明"
    服务器上的 Gemini 密钥无效时，所有批次都会失败，结果显示为降级，界面不提示密钥问题。每次生成都降级时，请系统管理员检查密钥。

## 生成失败与重试 {#sec-um-gen-fail}

{{i:重新生成}}任务无法创建、执行失败或等待超时时，卡片显示错误原因。主按钮变为[[重新生成内容]]（[@fig-um-gen-failed] 中编号 1），旁边多出[[重新生成]]按钮（编号 2）。两个按钮作用相同：重新检查框架，确认后重新提交任务。

![生成失败后的卡片](shot:gen-failed){#fig-um-gen-failed .w95}

常见的失败原因见[@tbl-um-gen-errors]，全部提示原文见[@app-um-messages]。

Table: 生成失败的常见提示 {#tbl-um-gen-errors cols=50,50}

| 提示 | 处理办法 |
|---|---|
| “服务端未配置 GEMINI_API_KEY，无法调用内容生成。” | 联系系统管理员配置密钥 |
| “内容生成失败：Gemini 调用频率或额度受限，请稍后重试。” | 等几分钟后重新生成；反复出现时联系系统管理员 |
| “内容生成失败：输入内容过长触发上游限制，请减少文档长度后重试。” | 删去文档中与汇报无关的部分，重新上传后再生成 |
| “内容生成失败：Gemini 上游服务暂时不可用，请稍后重试。” | 稍后重新生成 |
| “内容生成失败：Gemini 返回格式异常，请稍后重新生成。” | 重新生成 |
| “内容生成失败：异步任务等待超时，请点击“重新生成”。” | 浏览器等待超过 20 分钟。重新生成；反复出现时减少子章节数量 |
| “内容生成失败，请稍后重试。” | 网络中断或后端没有响应，检查网络后重新生成 |

## 生成期间的限制 {#sec-um-gen-limits}

{{i:生成任务/限制}}从点击[[开始生成]]到对话框关闭，页面处于锁定状态：

- 对话框一直打开，框架、步骤条、导航按钮和[[开始新任务]]都不能操作。
- 卡片中显示警告“AI 处理中，请勿刷新或关闭页面，避免任务中断。”。
- 刷新或关闭页面时，浏览器先弹出离开确认。

!!! warning "注意"
    生成期间刷新或关闭页面，文档和框架全部丢失，后端的任务虽然继续执行，但结果无法取回，只能重新上传、重新生成。
