# 上传文档 {#ch-um-upload}

“上传文档”是第 1 步。你在这一步填写封面信息，选择一份文档。浏览器在本地提取文档中的文字，文件本身不发送到服务器。

## 基础设置 {#sec-um-basic}

{{i:基础设置}}[[基础设置]]卡片在页面左上方，有 3 个输入框，如[@fig-um-basic] 所示。各输入框的规则见[@tbl-um-basic]。

![“基础设置”卡片和处理日志](shot:upload-settings){#fig-um-basic .w40}

Table: 基础设置的输入框 {#tbl-um-basic cols=8,14,26,52}

| 编号 | 输入框 | 默认值 | 规则和用途 |
|---|---|---|---|
| 1 | [[目标页数]] | 20 | 最小为 4，输入更小的数会自动改为 4。当前版本不使用这个值，演示文稿的页数由章节结构决定，见 [@sec-um-pages] 节 |
| 2 | [[汇报人]] | 空 | 可选。填写后显示在 PPTX 封面上；留空则封面不显示汇报人 |
| 3 | [[所属机构]] | 机械工业仪器仪表综合技术经济研究所 | 显示在 PPTX 封面和结束页上；清空则两处都不显示 |
| 4 | 处理日志 | — | 记录选择文件和解析的过程，见 [@sec-um-upload-log] 节 |

{{i:封面信息}}[[汇报人]]和[[所属机构]]在文档解析成功的那一刻记录下来。解析之后再改这两个框，封面不会变化；要改封面上的值，先改好输入框，再重新上传文档。

!!! warning "注意"
    离开“上传文档”步骤再回来，这两个输入框会恢复为默认值，但已经记录的值不变。此时如果重新上传文档，要先重新填写，否则封面上的汇报人会被清空。

封面上的其余内容由系统自动填写：标题取文档文字的第一行；日期取生成内容那天的日期，格式为“2026-10-03”。日期按世界协调时计算，北京时间 0～8 点生成时会早一天。这两项在系统里不能修改，只能在导出后用 PowerPoint 修改。

## 选择文档 {#sec-um-select}

{{i:上传文档}}填好基础设置后，按下面的步骤上传文档。

1. 点击[[上传文档]]卡片中的[[点击选择文档]]区域，即[@fig-um-upload-done] 中编号 1。系统打开文件选择窗口。
2. 选择一个 .pdf 或 .docx 文件，点击“打开”。区域下方显示文件名和大小（编号 2），区域中的文字变为[[解析中，请稍候…]]。
3. 等待解析完成。处理日志显示“文档已解析并可进入下一步。”，[[文档摘要]]（编号 3）显示这份文档的标题、领域、关键词和摘要。

    ![上传完成后的“上传文档”卡片](shot:upload-done){#fig-um-upload-done .w70}

文档要满足[@tbl-um-upload-rules] 中的条件。

Table: 上传文档的规则 {#tbl-um-upload-rules cols=18,82}

| 项目 | 规则 |
|---|---|
| 格式 | .pdf 或 .docx，按文件扩展名判断，不区分大小写。不支持 .doc |
| 大小 | 不超过 20 MB |
| 数量 | 每次 1 个文件，文件选择窗口中只能选一个 |
| 解析时限 | 45 秒，超时按失败处理 |
| PDF | 只提取文字层。扫描件和图片型 PDF 没有文字层，提取不到内容 |
| DOCX | 提取正文文字，不提取图片 |
| 拖放 | 不支持。把文件拖到页面上，浏览器可能直接打开或下载这个文件；打开 PDF 时会离开 ITEISlides，当前进度丢失 |

文字很多的文档，发送给 AI 时会截掉超出部分，见 [@sec-um-ai-data] 节。

## 文档摘要 {#sec-um-summary}

{{i:文档摘要}}[[文档摘要]]用固定规则从提取的文字中截取，不经过 AI。它的用途是让你确认文字提取是否正常：标题对不对、有没有乱码。4 个项目的取值规则见[@tbl-um-summary]。

Table: 文档摘要的取值规则 {#tbl-um-summary cols=14,86}

| 项目 | 取值规则 |
|---|---|
| [[标题]] | 文档文字中第一个非空行。这一行同时用作 PPTX 封面的标题 |
| [[领域]] | 文件类型，显示 PDF 或 DOCX |
| [[关键词]] | 把第 2～20 行按标点和空格切开，取前 8 个不少于 2 个字的片段，用顿号连接 |
| [[摘要]] | 文档文字的前 160 个字符 |

{{i:封面标题}}封面标题直接取第一行。如果文档第一行是“附件 1”、标准编号或页眉文字，封面标题就会出错。遇到这种情况，在 Word 中把标题移到第一行，另存后重新上传。

## 处理日志 {#sec-um-upload-log}

{{i:处理日志}}处理日志在[[基础设置]]卡片下方，每行以“[时:分:秒]”开头，记录本次进入“上传文档”步骤以来的操作，如[@fig-um-upload-log] 所示。

![处理日志](shot:upload-log){#fig-um-upload-log .w40}

正常上传会依次出现 4 行：“等待上传文档…”“已选择文件：文件名”“开始提取并分析文档内容…”和“文档已解析并可进入下一步。”。出错时，日志增加一行红色的错误原因，行首带“错误”二字，同样的原因也显示在[[上传文档]]卡片中。

离开这一步再回来，日志会清空，只剩“等待上传文档…”一行。

## 重新上传 {#sec-um-reupload}

{{i:重新上传}}在“上传文档”步骤，随时可以上传另一份文档。新文档解析成功后，系统做以下处理：

- 用新文档替换旧文档，封面标题改为新文档的第一行。
- 清除已生成的内容、导入的图片、审计修改和导出结果。
- 保留“规划框架”中的章节结构。

新文档解析失败时，旧文档和已生成的内容都保留，[[文档摘要]]仍显示旧文档。

!!! warning "注意"
    在已经生成内容、导入图片之后重新上传文档，这些工作会全部清除，而且不弹出确认对话框。

## 常见情形 {#sec-um-upload-cases}

上传出错时，错误原因同时显示在[[上传文档]]卡片和处理日志中，[@fig-um-upload-errors] 是其中两种。全部情形见[@tbl-um-upload-cases]。

![上传出错时卡片中的提示](shot:upload-errors){#fig-um-upload-errors .w60}

Table: 上传文档的常见情形 {#tbl-um-upload-cases cols=22,40,38}

| 情形 | 软件的表现 | 处理办法 |
|---|---|---|
| 选择了 .doc 或其他格式的文件 | 提示“文件格式不支持，仅允许 .pdf / .docx。” | 用 Word 打开，另存为 .docx |
| 文件超过 20 MB | 提示“文件过大，请上传不超过 20MB 的文档。” | 压缩文档中的图片，或删去与汇报无关的附录后另存 |
| 扫描件 PDF | 提示“未提取到有效文本，请确认文件不是扫描图片或加密文档。” | 改用原始 Word 文件，或先用 OCR 软件转成可以选中文字的 PDF |
| 设置了打开密码的 PDF，或文件已损坏 | 提示“文档解析失败，请检查文件是否损坏后重试。” | 去掉密码后另存，或换一份完好的文件 |
| 解析超过 45 秒 | 提示“解析超时，请压缩文件体积或稍后重试。” | 减小文件体积；关闭其他占用资源的程序后重试 |
| 摘要中出现乱码 | 文件可以上传，但 AI 得到的也是乱码 | PDF 中的字体编码无法识别，改用 Word 文件上传 |
| 封面标题不对 | 文档第一行不是标题 | 把标题移到第一行后重新上传，见 [@sec-um-summary] 节 |
| 解析后修改了汇报人 | 封面仍是解析时的值 | 改好后重新上传文档 |
