# 产品需求：ITEISlides 智能汇报 PPT 生成

本文是重构前按现有系统重建的需求基线。事实来源：`docs/ITEISlide使用手册.pdf`（现行手册）和 2026-10-03 的代码。手册与代码不一致的地方，以代码为准，差异列在第 11 节。

## 1. 背景

ITEI 的业务骨干和科研人员经常要把一份长文档（标准送审稿、研究报告）整理成汇报 PPT，并套用所内模板。手工排版耗时，内容取舍也容易遗漏。

## 2. 要解决的问题

用户上传一份 `.pdf` 或 `.docx`，系统用 Gemini 规划章节、生成逐页正文、表格和配图提示词，用户导入配图、逐页审阅后，导出符合所内模板的 `.pptx`。

## 3. 目标

- 4 步完成：上传文档 → 规划框架 → 配图导入 → 审计预览（含导出）。
- AI 起草，人工把关：每页标出内容来源、AI 补充项和缺失项。
- 导出的 PPTX 套用所内模板的版式、颜色和字号。

## 4. 不做的事

- 不支持一次上传多个文件，不支持 `.doc`、扫描件和加密文档。
- 不在系统内生成图片。配图由用户在 ITEI DRAW 平台生成后上传，或上传本地图片。
- 不保存历史任务和导出版本，不做用户账号。
- 不提供 PPT 在线编辑器。审阅只能改正文和表格单元格。
- 不做多人协作。

## 5. 用户与角色

| 角色 | 需要 |
|---|---|
| 汇报人（业务骨干、科研人员） | 快速得到可用的 PPT 初稿，并能核对每页内容出处 |
| 运维人员 | 配置 Gemini Key、部署前后端、清理过期任务 |
| 开发人员 | 本地一条命令起前后端，不依赖 Firebase 即可调试完整流程 |

## 6. 使用场景

用户打开页面，在“基础设置”填写汇报人和所属机构，上传送审稿 `.docx`。解析完成后进入“规划框架”，保留默认的“自定义”模板，点“AI 建议调整”得到 6 个章节和每页的布局建议，改掉不合适的章节名称，删掉一个不需要的子章节，点“开始生成内容”。生成完成后进入“配图导入”，复制图片描述到 ITEI DRAW 生成图片，再上传到对应槽位。最后在“审计预览”逐页核对正文，把超过 150 字的正文改短，点“生成 PPTX”并下载。

## 7. 功能需求

### FR-001 上传并解析文档

用户一次上传 1 个 `.pdf` 或 `.docx` 文件，大小不超过 20 MB。系统在浏览器内提取纯文本，45 秒超时。以下情况给出中文提示且不进入下一步：`.doc` 文件、其他格式、超过 20 MB、一次选多个文件、提取不到文本、解析超时、文件损坏。

**验收：** AC-001、AC-002

### FR-002 基础设置与封面回填

“基础设置”有 3 项：目标页数（默认 20，最小 4）、汇报人（可选）、所属机构（默认“机械工业仪器仪表综合技术经济研究所”）。解析成功后，文档首个非空行作为封面标题（为空时用去掉扩展名的文件名），汇报人写入封面，所属机构写入封面和结束页。

**验收：** AC-003

### FR-003 文档摘要与处理日志

解析后显示文档摘要：标题、领域（文件类型）、关键词（第 2～20 行里长度不小于 2 的前 8 个词）、摘要（正文前 160 字）。日志区按时间记录选择文件、开始解析、解析结果和错误。

**验收：** AC-004

### FR-004 四步导航与进入条件

页面顶部是 4 步步骤条。进入“规划框架”需要已解析文档；进入“配图导入”和“审计预览”需要已生成内容，且生成后框架没有再改动。条件不满足时，“下一步”不可用，并显示原因。切换步骤、上一步、下一步都要先在确认弹窗里确认。所有确认弹窗在点确认后保持打开、两个按钮不可用，直到对应操作完成才关闭（生成内容、AI 建议调整、生成 PPTX 都是如此）。

**验收：** AC-005、AC-006

### FR-005 开始新任务

页眉的“开始新任务”按钮经确认后，清空文档、框架、已导入图片、审阅修改和导出结果，回到“上传文档”。

**验收：** AC-007

### FR-006 预设模板

“预设模板”有 3 个选项：标准审查汇报（章节取自所内模板）、学术研究汇报（4 章 8 个子章节）、自定义（默认，无章节，由 AI 生成）。切换模板时保留封面和结束页信息。“重置默认”经确认后，按当前模板恢复章节结构。

**验收：** AC-008

### FR-007 编辑章节框架

主表 5 列：序号、章节名称、子章节数、内容、删除。点章节左侧箭头展开子章节表，同一时间只展开一个章节。子章节表 5 列：序号（层级编号 `1-1`）、子章节名称、布局提示（只读：文字 / 文字 + 表格 / 文字 + 图片）、内容（AI 理由）、删除。规则：

- 章节名称、子章节名称可直接改。
- 子章节数取值 1～20，改小时从末尾截掉，改大时按最后一个子章节的布局补齐。
- 至少保留 1 个章节；每章至少保留 1 个子章节。
- 添加章节、添加子章节、删除章节、删除子章节都要确认。
- 页面底部显示预计页数 = 章节数 + 子章节总数 + 2（封面、结束页）。

**验收：** AC-009、AC-010

### FR-008 AI 建议调整

右侧悬浮按钮“AI 建议调整”经确认后，把当前章节和文档正文发给 `/api/plan`。返回后：

- 每章显示覆盖度（高覆盖 / 中覆盖 / 低覆盖）和 AI 理由，顶部汇总覆盖度计数。
- 每个子章节的布局提示改为 AI 决定的“文字 + 表格”或“文字 + 图片”。
- “自定义”模板下不足 6 章或某章不足 2 个子章节时，后端用固定章节补齐，再请 AI 评估。空框架得到“一、背景与目标”到“六、结论与建议”6 章（见 Q-8）。
- Gemini 返回异常或非鉴权错误时，后端改用本地规则生成理由和布局，流程不中断。服务端缺 Key 时明确报错。

**验收：** AC-011、AC-012

### FR-009 生成逐页内容

“开始生成内容”先校验章节名称和子章节名称不为空，再经确认后创建异步生成任务，每 2 秒查询一次进度，显示百分比和阶段文字。规则：

- 任务成功后显示已生成页数和原文覆盖率。
- 任务失败或等待超过 20 分钟，显示原因和“重新生成”。
- 进行中的任务 ID 和框架摘要写入 `sessionStorage`。“规划框架”页面重新挂载时，若文档已解析且框架摘要相同，自动恢复查询；不同则清除记录。生成期间导航和“开始新任务”都不可用，刷新后框架回到默认，所以现有界面中恢复实际不会触发（见 Q-7）。
- 生成期间离开页面会弹出浏览器的离开确认。
- 生成后再改框架，原结果作废，提示重新生成。
- 后端部分批次失败时，结果标记为降级，页面提示“已降级生成，可继续编辑”。

**验收：** AC-013、AC-014、AC-015、AC-016

### FR-010 生成结果的结构

生成结果按顺序包含：封面、每章一张目录过渡页（高亮当前章）、每个子章节一张正文页、结束页（“敬请指正”）。每张正文页有：正文（不超过 220 字）、语义高亮范围（最多 2 处，短语优先、整句兜底）、来源引用和置信度、AI 补充项；表格页有表格，图片页有配图提示词。正文少于 30 字、低证据补写或批次失败的页面计入缺失项。

**验收：** AC-017

### FR-011 配图导入

只列出“文字 + 图片”页面，每页按配图提示词数量分槽位，默认展开第一页。规则：

- 每个槽位可“复制图片描述”“上传图片”（已有图片时为“替换图片”）、“移除”，上传、替换、移除都要确认。
- 只接受 `image/*`，单张不超过 12 MB。
- “批量导入图片”按页面顺序填充空槽位，多出的图片不使用并提示数量。
- 显示“已导入 x/y，待导入 z”。
- 右侧悬浮“ITEI DRAW”在新标签页打开 `https://draw.sensor-cloud.org/`。
- 没有图片页时提示可直接进入审计预览。

**验收：** AC-018、AC-019、AC-020

### FR-012 审计预览

顶部显示总页数、原文覆盖率、AI 补充项、缺失项和源文件清单。逐页审阅区：

- 筛选：仅正文（默认）、全部页面、仅问题页。
- 左侧按章节分组，手风琴式展开；右侧显示 16:9 预览和 4 个页签：溯源、正文编辑、AI补充、缺失项。
- “正文编辑”可改正文（显示“字数：n/150”）、表头和单元格；图片页显示各槽位是否已导入。
- 图片页预览优先显示已导入的图片。

**验收：** AC-021、AC-022

### FR-013 导出 PPTX

“PPT 导出”区显示总页数、图片页数、图片槽位“已导入/总数”和超过 150 字的页面，并给出对应警告。“生成 PPTX”经确认（含风险摘要）后在浏览器内渲染。渲染规则：

- 版式、背景、字号、颜色取自所内模板（`template_structure.json`）。
- 封面单标题；子标题蓝底按长度加宽或换行，正文下移避免重叠；正文高亮用模板强调色。
- 表格套模板表格样式；图片页有图片时放图片，没有时放“复制以下内容并在 ITEI Draw 生成PPT配图：”加提示词的占位文字。

生成成功后出现“下载生成文件”，确认后下载 `ITEIPPT_v2_output.pptx`。

**验收：** AC-023、AC-024、AC-025

### FR-014 后端 HTTP 接口

后端提供 `/api/health`、`/api/plan`、`/api/generate-content`（同步，保留给旧调用方）和 `/api/generate-content/jobs` 系列接口，契约见 `docs/API.md`。未定义的 `/api/*` 路径返回 404，不再转发到 Gemini。

**验收：** AC-026、AC-027

### FR-015 生成任务的存储与清理

线上任务状态存 Firestore（`generationJobs`），请求体和结果存 Cloud Storage，经 Pub/Sub 交给 worker 执行；任务 72 小时后由每日定时任务清理。worker 跳过已结束的任务和 10 分钟内仍在运行的任务。

**验收：** AC-028

## 8. 非功能需求

### NFR-001 Gemini Key 只在服务端

前端代码和构建产物里没有 Key。本地读 `src/.env`，线上读 Secret Manager。

**验证：** AC-030

### NFR-002 本地可完整运行

不依赖 Firebase，本地一条命令起前后端，能走完 4 步。

**验证：** AC-029

### NFR-003 导出结构符合模板

导出文件的页面结构与模板一致（结构门禁 `npm run gate:phase1`）。

**验证：** AC-024、AC-031

### NFR-004 界面符合 ITEI 设计规范

界面遵循 `design/itei/`：颜色、字体、直角、45° 斜切、焦点环、无 emoji，浅色和深色主题都可读。

**验证：** AC-032

### NFR-005 界面文字无乱码

前端源码中用户可见的中文没有编码损坏。

**验证：** AC-033

### NFR-006 存储默认拒绝

客户端不能直接读写 Cloud Storage；后端通过 Admin SDK 访问。

**验证：** AC-034

## 9. 约束与假设

- 技术栈按 `TechStack/webapp.md`：React 19、TypeScript 7、Vite 8、Tailwind CSS 4、shadcn/ui。
- 线上部署在 Firebase（Hosting、Functions Gen2 `asia-east1`、Firestore、Cloud Storage、Pub/Sub、Cloud Scheduler）。
- 模型默认 `gemini-2.5-flash`，可用环境变量改。
- 用户能访问 Google 服务。面向中国大陆用户时需另行验证可达性。

## 10. 边界情况

- 正文超过 18 万字符时，生成只取前 18 万字符；规划只取前 12 万字符。
- 生成接近 500 秒软时限时，剩余批次直接用本地规则补写并标记降级。
- 批量导入的图片多于空槽位时，多余图片不使用。
- 框架改动后，已导入的图片保留，但“配图导入”和“审计预览”在重新生成前不可进入。

## 11. 待定问题与已知差异

| 编号 | 内容 | 现状 |
|---|---|---|
| Q-1 | “目标页数”不影响生成 | 代码未使用该值，手册称“期望生成的 PPT 总页数”。待用户决定删除还是接入 |
| Q-2 | 章节超过 6 个时导出失败 | 模板目录页只有 6 行，渲染抛出“row layouts are fewer than section items”。AI 可能生成 8 章 |
| Q-3 | “AI补充”页签只能查看 | 手册写“确认或删除”，代码只列出补充项 |
| Q-4 | SVG、WEBP 图片导出 | 允许上传，导出时可能失败；旧进度记录称已转 PNG，代码中没有 |
| Q-5 | 后端提示词有 5 处乱码 | 两处 JSON 结构提示、一处“文档内容如下”、一处章节序号正则、一处高亮停用词“说明”。影响 AI 输出质量和降级覆盖度判断 |
| Q-6 | 章节名称编辑方式 | 手册写“双击即可修改”，代码为单击输入框直接改 |
| Q-7 | 刷新后无法恢复生成任务 | 部署文档称“页面刷新后自动恢复轮询”。刷新后框架回到“自定义”空章节，摘要不同，记录被清除，任务结果无法取回 |
| Q-8 | “自定义”模板的章节不是 AI 生成的 | 手册写“框架完全由 AI 基于上传文档自动生成”。后端先用固定 6 章补齐再调 AI，AI 草拟章节的分支走不到，AI 只给理由、覆盖度和布局 |
| Q-9 | 开发服务器下生成任务不结束 | `npm run dev` 启用 React StrictMode，`FrameworkPlanner` 的卸载标记在模拟卸载后不复位，第一次查询后停止轮询。生产构建不受影响。**已在重构中修复**（`useGenerationJob` 挂载时复位标记），`E2E_DEV=1 npm run e2e:local` 在开发服务器上验证 |
